# Patente B بالعربي — Copilot work brief

## Mission and non-negotiable boundaries

Help the owner build an exceptionally clear, reliable Italian category-B theory-learning experience for Arabic speakers. Work in small, reviewable increments on `audit/v67-dictionary-quality` only. Do not change, push to, merge into or rewrite `main`; do not transfer ownership, modify repository/account permissions, expose secrets, change signing keys, publish a release, or upload an AAB/APK. The owner reviews changes, tests the app, and signs the AAB. Use free tooling only; do not activate trials, paid models, extra usage, chargeable quotas or services without explicit approval. Preserve existing access/subscription rules and Firebase Spark.

**Do not equate a written plan, passing source-level tests, a PWA build, a successful push, or an unverified CI run with a tested Android release.** Cite evidence and report gaps honestly. Do not claim the app is the best in the world or that every defect has been found.

## Priorities and acceptance criteria

### P0 — correctness and legal safety

- Correct Q19550 and systematically compare Italian question wording, answer, road sign/image and Arabic meaning, prioritizing negation, prohibitions, exceptions, numbers, priority and dangerous mistranslations. Preserve official VERO/FALSO answers unless a current official list establishes an error. Record each checked question ID, discrepancy, evidence, change and unresolved issue; use automated checks for suspect language patterns plus human/contextual review. Do not invent official wording or silently mark unsupported content as verified.
- Verify the full category-B syllabus, lesson explanations, questions and illustrations against current Italian primary sources. Start with the [Portale dell'Automobilista's exam and quiz page](https://www.ilportaledellautomobilista.it/web/portale-automobilista/foglio-rosa-e-prove-new) and the current consolidated [Codice della strada on Normattiva](https://www.normattiva.it/uri-res/N2Ls?urn:nir:stato:decreto.legislativo:1992-04-30;285); consult relevant official decrees and authoritative listati linked there. Record source URLs, relevant articles/list versions and access dates in an auditable coverage matrix. Recheck rules that may have changed rather than trusting static or unofficial material. The official exam page specifies 30 questions, 20 minutes and at most 3 errors for the standard exam; it also describes DSA accommodations, which should not be misrepresented.
- Cover the full category-B syllabus in **exactly 50 lessons across 11 units**. Preserve lesson identifiers and order; update only supplied/authorized lesson IDs. Every lesson must expose `id` (`uN-lN`), `titleIt`, `titleAr`, `summaryIt`, `summaryAr`, `keyPoints`, nullable `trapWord`, and `quickChecks`: 3–4 key points and exactly three VERO/FALSO checks. A null `trapWord` is allowed; the baseline's 50 nulls are not in themselves a defect. Add schema, uniqueness, ID-preservation, source-coverage, bilingual meaning and consumer compatibility tests. Provide a safe migration for existing lesson progress.

### P1 — Arabic-first learning and accurate vocabulary

- Explain Italian rules in clear, natural Arabic with accurately aligned Italian examples. Review translations in their actual sentence and sign context, including polarity and inflected/attached-pronoun forms. On content edits, compare essential new vocabulary against the tappable dictionary and add missing word forms and contextual translations. Resolve entries only with documented evidence; leave ambiguous entries flagged for review. Keep SQLite, source JSON, app lookup and recorded SHA in sync, verify database integrity and test dictionary lookup offline.
- Preserve an uninterrupted vertical learning path with current, completed and locked states. Correct on the first attempt schedules review after three days; a wrong answer schedules review the following day, with an error-review flow. Test date boundaries, repeat attempts, persisted progress, offline use and synchronization without losing learning history.
- The simulator uses 30 questions, a 20-minute timer, fails at the fourth error and offers an unanswered-question review sheet. Add behavioral tests for 3 vs 4 errors, timeout, skipped/unanswered questions, resume, scoring, accessibility and offline operation. Distinguish the app's early-fail behavior from official exam mechanics if presenting it to learners.

### P1 — Android, accessibility and secure synchronization

- Use Android Native `TextToSpeech` for Italian (`it-IT`, rate `0.8`, pitch `1.0`); eliminate Web Speech conflicts. Test language availability, playback, cancellation, lifecycle, speed/pitch, error states and repeat playback on an actual device or working emulator. Source-level checks alone are not runtime evidence.
- Preserve secure sign-in and synchronization without exposing private data or secrets; test Firebase Authentication/Firestore security rules, cross-device restoration, account switching, conflict/retry behavior, offline changes and reconnect. Stay within Firebase Spark and existing subscription/access rules. Do not weaken security rules to make tests pass; avoid real personal data in fixtures.
- Preserve offline learning, synchronized illustrations/3D with the corresponding explanations, and enlarged readable Italian subtitles. Test first load versus previously cached use, connectivity loss/recovery, content versioning and visual/audio synchronization. Do not assume that an offline cache declaration proves offline behavior.
- Use a modern, high-contrast dark interface without white surfaces. Test Arabic RTL and Italian LTR, long text, wrapping, no text/image overlap or clipped controls across representative small and large Android screen sizes, font scaling and orientations; record contrast measurements and screenshots. Keep progress, statistics, topics, results, assistant and search off the home screen. Android Back returns internal screens home, then exits from home; do not add «إلى الهاتف».

## Validation and delivery required for each change

1. Document exact changed files and lesson/question/dictionary IDs, rationale and official sources; preserve untouched data and owner rules. Separate confirmed defects, remaining uncertain findings and untested features. Do not reduce coverage or hide failing tests.
2. Run `npm run build`, relevant focused tests and `npm test` where feasible; supply commands, exit codes, counts and log references. Check the dictionary SHA, JSON/SQLite parity and `PRAGMA integrity_check` whenever the dictionary changes. Report CI as successful only if the actual run succeeds.
3. Provide reproducible mobile viewport/contrast/overflow evidence and Firebase security/sync test results. Build and install an Android debug build in a suitable environment and provide runtime evidence for audio, navigation, offline behavior and login/sync; if any prerequisite is unavailable, report the exact blocker instead of declaring completion. Never require the owner to provide phone debugging access.
4. Deliver a concise per-increment summary with remaining `review_required` count, failed or skipped checks, official-source citations, Android/PWA validation status and risks. Keep changes on the audit branch for owner review; no release, main merge or signature.
